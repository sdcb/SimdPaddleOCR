# .NET 11 RC1 vs .NET 10（2026-09）

对照 [perf.md](perf.md) 的 CI 基线，看同一套 PP-OCRv6 tiny 推理在 **.NET 11 RC1** 上有没有可分辨的快慢变化。
结论先说：**没有大台阶。** 稳的平台上大约快 **0–2.5%**，正确率完全一样。macOS 那组看起来快 20%，不可信。

## 怎么读

- 墙钟、IQR、范围、`n` 的定义与 [perf.md](perf.md) 相同：去掉 warmup 后的 **median ms/图**，再对 replica 中位数取中位。
- **只比同一 CPU + 同一有效 ISA + 同一套件。** 不要把 7763 AVX2 和 Xeon AVX-512 的绝对毫秒混在一起。
- .NET 10 侧是 5 次 `test` 工作流的合计；.NET 11 侧只有 1 次。后者样本少，小于约 **2%** 的差应先当成 runner 噪声。
- 引擎套件里的 lw.PPOCR.C / OpenVINO.NET 是原生库，**不走 .NET JIT**，用来当噪声对照：它们若也变 1%，说明是机器而不是运行时。

## 正确率

本库（sharp）在 .NET 11 RC1 上与 .NET 10 完全一致：bench **757/1022**、CER **3.53%**；tiny smoke **152/208**。lw.PPOCR.C 仍是 759/1022 / 4.18%，OpenVINO.NET 仍是常见的 698/1022 / 3.63%。没有因换运行时改识别结果。

## 够稳、可以下结论

下面只列 **两边都有足够同 CPU 样本** 的用例。变化 =（.NET 11 中位 − .NET 10 中位）/ .NET 10 中位。负值表示 .NET 11 墙钟更短。

## 不要用来下结论

### osx-arm64（Apple M1 Virtual）

`tiny-4w` 中位 341.5 → 261.8（**−23%**），`tiny-1w` / ns2 也大约 −20%。perf.md 已把这台 3 核 / 7 GB 虚拟机标成高噪声平台：replica 可以差一倍。

.NET 11 的 `tiny-4w` 范围 239–280，**完全落在** .NET 10 的 223–484 里，只是这次 5 个 replica 抽到比较安静的一组（IQR 260.7–266.3，异常窄）。工作集约 728 → 788 MB（+8%），方向和墙钟「变快」也不一致。

**不要把 macOS 写成「.NET 11 快 20%。」**

### 样本不够的 x64 主机

| 平台 / 用例 | .NET 10 | n | .NET 11 | n | 表面变化 | 原因 |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| 引擎 9V74 AVX2 `tiny-4w` | 229.2 | 4 | 254.0 | 2 | +10.9% | 一台 281 ms 离群；同机 C / OpenVINO 也一起变慢 |
| SIMD Xeon 8573C AVX-512 `tiny-4w` | 156.1 | 1 | 149.2 | 1 | −4.4% | 各 1 replica |
| SIMD Xeon 8573C `tiny-4w-noavx2` | 358.8 | 1 | 326.4 | 1 | −9.0% | 同上 |

.NET 11 这次 SIMD 套件没有抽到 9V74；引擎套件没有抽到 Xeon。缺的那一侧无法比。

### smoke

每平台 1 次，CPU 还会变，**不能**和 100 张 bench 比，也不能单独证明运行时差异。同 CPU 的几条（7763 linux-x64 / win-x64 tiny、N2 linux-arm64）在 ±1–4% 里晃。`osx-x64` i7-8700B 779 → 374 这种直接丢掉——perf.md 里它的范围已经是 252–1081。

## 怎么读这 2%

| 平台 | 可信度 | 读数 |
| --- | --- | --- |
| linux-arm64 N2 | 高 | 大约快 2.3%；IQR 不重叠；MatMul 约快 7% |
| win-x64 7763 SIMD | 中 | `tiny-4w` −2.0%，但 IQR 重叠，同 ISA 的 `noavx512` 为 +0.5% |
| win-x64 7763 引擎 | 高（对照） | sharp 0.0%；原生 C / OpenVINO +1%，标定噪声 |
| osx-arm64 / smoke / n=1 | 低 | 不用于判定 |

综合：**.NET 11 RC1 对这套 tiny 推理没有可见回归，也没有 5% 以上的稳定收益。** 最像真的是 linux-arm64 大约快 2%；Windows 7763 在噪声里。正确率和 win/linux 工作集没变。

若要钉死那 2%，最省事是再跑一两次同一套 CI，只看 **Neoverse N2 的 `tiny-4w` / `tiny-1w`**。macOS 再加 replica 也很难单独说明 .NET 版本。
