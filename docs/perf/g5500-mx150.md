## 小结

* **SSE4.2 CPU 全档快于 `v2.0.0`**：**1.18× (`tiny`) / 1.27× (`small`) / 1.09× (`medium`)**。本轮宿主机较空闲，绝对值比上一版报告（`tiny` 511 ms，当时有约 23% 后台负载）快。
* **GeForce MX150 Vulkan**：`tiny` **2.61×**（714.5 → **273.3 ms**）、`small` **4.21×**（3143.5 → **747.4 ms**）、`medium` **2.76×** 且不再 DeviceLost。相对本机 G5500 CPU，MX150 领先 **1.41× / 1.86× / 2.33×**。
* **内存**：加载后工作集全档低于 `v2.0.0`（`tiny` 398 → 382 MB、`medium` 377 → 338 MB）；CPU `medium` 峰值 781 → 749 MB。
* **精度**：`small` 25 张 247 → 250 行，但 CER 0.67% → 0.71%（25 张子集样本较小，同一输出在 100 张全集上 CER 下降）；`medium` 6 张不变。100 张全集的结论见 [`5800x-rtx3080ti.md`](5800x-rtx3080ti.md#小结)。

## 历史：SSE4.2 专用核优化要点（2026-11-27）

* **SSE4.2 CPU 从显著回退转为全档反超 `v2.0.0`**：相对优化前 `main` (`91f1d14`) 分别提速 **1.51× (`tiny`) / 1.68× (`small`) / 1.19× (`medium`)**，相对 `v2.0.0` 全档胜出 **1.17× / 1.23× / 1.11×**。核心优化位于 `SimdOnnx` 严格按 `!UseAvx && !UseAvx512 && !UseNeon && !UsePacked && Sse.IsSupported` 门控的 x64 SSE 专用路径（不影响 AVX-512 / AVX2 / ARM64 NEON / WASM）：
  1. **`SimdMath` 无硬件 FMA 路径修复 + `Sse.Max` Softmax**：`ExpCore`/`ErfCore` 在 `!Fma.IsSupported && !AdvSimd.IsSupported` 时改为 `mul + add`（消除每向量 4 次标量 `fmaf` 调用），并将 `SoftmaxRow` 最大值归约改为单条 `Sse.Max` 指令，`small`/`medium` 的 `Softmax` 从 `2544 / 1702 ms` 降至 **`9.3 / 5.5 ms`**（快 273×–309×）。
  2. **16-XMM 零溢出 `6×8` 卷积条带核 & `2×16` 深度卷积核**：新增 `Nhwc.Sse.cs`，将 `6×8` 累加（12 累加 + 2 权重 + 1 广播 + 1 临时 = 16 XMM 满载零溢出）按 48 像素条带合并进单次 `[NoInlining]` 调用（Windows x64 `xmm6..xmm15` 仅保存一次，且去掉栈零化与直写 `None`/`Relu` 路径），配合 `2×16` `kw==3` 展开深度卷积与 `SseTile = 6`（Winograd / 通用卷积）。
  3. **24 行分块 `6×8` `MatMulArgMax` 与 SSE `LayerNorm` / `GemmKN`**：`MatMul.Sse.cs` 对 18385 类分类头做 24 行分块复读权重并修复 `Sse.Multiply(v, w)` 操作数序，在仅 3 MB L3 的 G5500 上大幅降低 DRAM 访存，`MatMul` 较 `v2.0.0` 提速 **1.95×–2.54×**。
